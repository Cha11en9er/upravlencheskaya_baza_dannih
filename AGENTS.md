# Правила работы с проектом УБД (Dmitiy_stroitelnaya_kompaniya)

Обязательно для каждой рабочей сессии (человека и агента). Формат подсмотрен в
`C:\repos\YouDo\vlad_bit_it\files_transformer` (там узконаправленные правила под
Excel-трансформер — здесь обобщены под этот проект).

## 1. Фиксация работ — roadmap/ (главное правило)

- **Каждая рабочая сессия** создаёт/ведёт файл `roadmap/ДД.ММ.ГГ_summary.md`
  (например `19.11.26_summary.md`). Один файл = один день работы.
  Если файл дня уже есть — дополнять его.
- В начале сессии: одна строка — цель сессии.
- По ходу: тезисно, что сделано / что выяснено / что сломалось и как починено.
- В конце: итог — что работает, что нет, что дальше.
- Стиль: короткие тезисы, по-русски, без воды; даты/числа/команды — как есть.
- Постоянные справки, к которым возвращаемся (сервер, схема БД, деплой, входы),
  — отдельные файлы в `roadmap/notes/*.md`; при изменении фактов обновлять их,
  а не плодить дубли в дневных файлах.
- В конце сессии — commit с осмысленным сообщением и push.

## 2. Секреты

- Пароли, токены, ключи в репозиторий не класть: `.env` игнорируется
  (шаблон без секретов — `ubd/backend/.env.example`).
- В md-файлах пароли не печатать. Выдавать пароль в чате или хранить в
  git-ignored файлах на машине/сервере.
- К серверу — только по ssh-ключу (алиас в `~/.ssh/config`), парольный перебор
  запрещён.

## 3. Данные

- В git — только код и документы. Большие датасеты (`data/synaps/`, `export/`)
  и выгрузки в репозиторий не коммитить (см. `.gitignore`); они лежат локально
  в папке проекта и на сервере доставляются отдельно (scp).
- Файлы >50 МБ в git не класть вообще.

## 4. Самопроверка каждого действия

- Изменил код → `python -m py_compile app/**/*.py` и `pytest tests -q`
  (из `ubd/backend`; на 19.11.26 — 22 теста) до коммита.
- Задеплоил → смоук-скрипт curl: логин, страницы блоков, экспорт xlsx
  (чек-лист в `roadmap/notes/server-uchgrad.md`).
- Решение принял → почему, записать в дневной файл; постоянное решение →
  `ubd/docs/DECISIONS.md`.

## 5. Деплой (кратко, детали в `roadmap/notes/server-uchgrad.md`)

- Сервер: `ssh uchgrad-vps` (root@201.34.143.208, ключ `~/.ssh/id_ed25519_uchgrad`).
- Приложение: `/opt/ubd`, systemd `ubd.service`, порт **8010** (8000 занят другим
  приложением), БД — серверный PostgreSQL 18 (база `ubd`, роль `ubd_app`).
- Порядок: push в GitHub → на сервере `cd /opt/ubd && git pull` →
  если менялись зависимости: `..venv/bin/pip install -r ubd/backend/requirements.txt`
  → `systemctl restart ubd` → curl-смоук снаружи.

## 6. Стиль кода УБД

- Все калькуляции — только в `ubd/backend/app/calc.py` + `services/recalc.py`,
  каждая с тестом в `tests/test_calc.py`.
- Права доступа — только через фабрику `require_block` в роутерах.
- Деньги — целые рубли (int), копеек нет (ТЗ п.9.2).
- В роутерах `Request` всегда импортировать из fastapi (грабля future-annotations).
- Суммы оплат договора — SQL-агрегатом, не по кэшированной коллекции.
- Цвета/риски — палитра ТЗ: green #C8E6C9, yellow #FFF9C4, red #FFCDD2,
  шапки #1E3A5F.
